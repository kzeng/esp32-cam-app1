## 构建与硬件

- [ ] 实物确认为 AI Thinker 引脚配置兼容的 ESP32-CAM。

- [ ] 成功烧录，移除 IO0–GND 下载连接后正常启动。
- [ ] 摄像头初始化成功、PSRAM 可用，串口打印实际 IP。
- [ ] 路由器为摄像头保留 IP；不设置公网摄像头端口映射。
- [ ] 移除串口连接，只使用独立电源，摄像头仍能工作。

## Ubuntu 服务与访问保护

- [ ] 安装 requirements 成功，正确配置 `.env`，权限为 600。
- [ ] 缺少或仍用占位密码／密钥时服务明确拒绝启动。
- [ ] `/healthz` 可返回；另行打开页面确认真实画面，不以健康接口代替硬件验证。
- [ ] 未登录请求 `/api/status`、`/api/stream`、`/api/snapshot` 得到 401。
- [ ] 错误网页密码不能登录；连续错误后短时间限制重试。
- [ ] 正确密码可登录；退出后不能再建立新的画面连接。
- [ ] 画质 POST 缺少有效 CSRF token 时被拒绝。
- [ ] 改错网关摄像头密钥后显示密钥错误；恢复后能继续看图。
- [ ] ESP32 直接接口缺少密钥时拒绝访问。

## 画面和手机操作

- [ ] 默认画面为 VGA；三档切换后下载的 JPEG 实际尺寸分别正确。
- [ ] 画质控制失败时不会在界面上假报成功。
- [ ] 网页补灯按钮可点亮／关闭 GPIO4 LED；未登录、无 CSRF 或无摄像头密钥时不可控制。
- [ ] 补灯点亮约 1 分钟后自动关闭，刷新页面和板端重启后按钮反映实际状态；断网时最终自动关闭。
- [ ] 拍照保存的是新获取图片，手机可通过下载链接保存并打开。
- [ ] 两个浏览器观看同一路画面，不出现两个独立摄像头采集线程。
- [ ] 达到观看连接限制时能恢复，不把摄像头长期卡死。
- [ ] 暂停／页面后台／关闭页面后，不再由该页面维持采集；允许在途请求超时后释放。
- [ ] 摄像头离线时不把最后一帧当作实时画面持续展示。
- [ ] 摄像头掉电再上电、Wi-Fi 断开再恢复后，页面可以重新显示画面。
- [ ] 浏览器不支持全屏时有提示，竖屏布局可操作。
- [ ] 手机上实际验证后台切换、返回页面、登录到期后的重连行为。
